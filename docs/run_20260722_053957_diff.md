**影響の評価**

| 指標 | 初期 `ind_000001`（3回平均） | 最良 `ind_000050`（3回平均） | 差分 |
|---|---:|---:|---:|
| fitness | 0.74325 | 0.77901 | +4.81% |
| planning_time | 0.004838 s | 0.004874 s | ほぼ同一 |
| path_length | 5.5206 m | 5.4279 m | -1.7% |
| arrival_time | 35.02 s（σ=5.27） | 28.70 s（σ=5.12） | -18% |

- `push_back`→`emplace_back` はコンストラクタのコピー削減のみを行うマイクロ最適化で、生成される経路や意思決定には影響しない。
- `arrival_time` の差（約6.3秒）は両個体の標準偏差（σ≈5〜5.3秒）とほぼ同オーダーであり、Gazebo/ROS シミュレーションの走行ごとのばらつきの範囲内に収まる。すなわち **今回観測された適応度向上（+4.8%）はコード変更由来ではなく、リピート評価間のノイズに起因する可能性が高い**。
- 系譜的には `ind_000050` は世代1で `crossover_and_mutation` により生成された `ind_000020`（ソース系統は `ind_000010.cpp`）を親に持つ `mutation_only` 個体。LLM（OpenAI gpt-4o-mini）によるコード生成の結果、ソースが偶然 `ind_000012.cpp` と同一（差分なし）になっている。

**補足**
- 実行レポートでは世代3の `ind_000050` が最良適応度 `0.77900709` を示すが、そのソースファイルは重複排除により `ind_000012.cpp` が使われているため、「初期→最良コード差分」は `ind_000001.cpp` と `ind_000012.cpp` の差分として記録されている。
- 結論として、この run では初期個体から最良個体までコード上の実質的な変更は `emplace_back` へのマイクロ最適化のみで、真の意味でのアルゴリズム改善（ヒューリスティックやロジックの変更）は確認できなかった。
