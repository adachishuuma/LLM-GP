# 30世代実験 チェックポイント検証レポート(初期個体・世代5・10・15・20・27)

`experiment_results/lattice_fork_minmax_30gen/run_20260908_110059/`(世代27/30で
中断)について、初期個体および世代5・10・15・20・27時点の最良個体を、それぞれ
ランダムなゴール(`goal_x_range=[15.0,16.5]`/`goal_y_range=[1.5,2.3]`)で**10回
再評価**し、統計的に検証した。詳細な結果全体は
[lattice_fork_minmax_30gen_experiment_report.md](lattice_fork_minmax_30gen_experiment_report.md)を参照。

## 対象個体

世代15・20・27の「その世代時点での最良個体」を調べたところ、いずれも
`ind_000111`(世代13生まれ)と**コードが完全に同一**(世代20の`mig_000172`は
`ind_000111`のmigration_copy=無変更コピー、生の指標も完全一致)だったため、
この3世代分は1回の検証で代表させた。検証対象は実質4個体:

| チェックポイント | 個体 | 生成方法 |
|---|---|---|
| 初期(世代0) | `ind_000008` | initial(無変更) |
| 世代5 | `ind_000031`(世代3生まれ) | crossover_only |
| 世代10 | `mig_000091`(=`ind_000054`と同一コード) | migration_copy |
| 世代15・20・27 | `ind_000111` | crossover_and_mutation |

初期個体(`ind_000008`)は既存の10回分データを再利用し、再評価は行っていない。

## 結果(初期個体との比較、各10回)

| 指標 | 初期個体平均 | gen5(`ind_000031`) | gen10(`mig_000091`) | gen15/20/27(`ind_000111`) |
|---|---:|---:|---:|---:|
| 成功率 | **100%(10/10)** | 40%(4/10) | 20%(2/10) | 60%(6/10) |
| ノード展開数 | 41,958 | 49,929(**-19.0%悪化**、p=0.037 有意) | 48,129(-14.7%悪化、p=0.258 非有意) | 20,190(**+51.9%改善**、p<0.001 有意) |
| 経路長 | 39.00 m | 37.82 m(+3.0%改善、p=0.036 有意) | 37.50 m(+3.9%改善、p=0.015 有意) | 38.63 m(+0.9%改善、p=0.324 非有意) |
| 到達時間 | **176.0秒** | 197.2秒(**-12.1%悪化**、p=0.001 有意) | 199.4秒(**-13.3%悪化**、p=0.015 有意) | 197.8秒(**-12.4%悪化**、p<0.001 有意) |

(改善率は「初期個体を基準に、値が小さいほど良い指標がどれだけ縮んだか」。負の値=悪化。太字は特筆すべき結果)

## 生データ(到達時間・成功可否)

初期個体は10回すべて168〜188秒で安定して成功している一方、進化した3個体は
**成功した試行でさえ192〜200秒とタイムアウト(200秒)直前に張り付いている**。
失敗も特定のゴール座標に偏っておらず(初期個体は同じ範囲の全ゴールで問題なく
成功しているため、ゴール自体の難易度が原因ではない)、進化した個体の実行その
ものが軒並み遅くなっていることを示している。

| | 初期個体(`ind_000008`) | gen15/20/27(`ind_000111`)の例 |
|---|---|---|
| 到達時間の範囲 | 168.8〜188.1秒(全10回成功) | 194.7〜200.1秒(6/10成功) |

詳細は`analysis/repeat10_logs/`配下の各`*_repetition_*.json`を参照。

## 実行環境の健全性の確認

この結果が例のGazebo実時間性能低下(Defenderの挙動監視によるもの、
[wsl_gazebo_troubleshooting_runbook.md](wsl_gazebo_troubleshooting_runbook.md)参照)
の再発でないことを、`gen15_20_27_ind_000111_repetition_1.roslaunch.log`の
リアルタイムファクター(RTF)を実測して確認した。

```
RTF ≈ 0.999〜1.000(定期的に一瞬0.5付近まで下がるが正常範囲)
```

RTFはほぼ1.0で健全だったため、**今回の結果は環境要因ではなく、個体自体の
実際の走行性能によるもの**と判断できる。

## 結論: なぜ前回(5世代実験)は改善したように見えたのか

前回(2026-09-08〜10の30世代実験)のGP実行中は、各個体は`repetitions_per_goal: 3`
(3回だけ、しかもそれぞれ別のランダムゴール)で評価されており、fitnessも
その少数サンプルの平均に基づいていた。**この少数サンプルでは、たまたま
経路長・到達時間が良く見える結果が出ていた**(実際、世代5・10時点の単発評価では
到達時間がわずかに改善して見えていた——本レポート冒頭で引用した
`generation_algorithm_report.md`の値を参照)。

しかし、ゴール範囲全体から**10個の新しいランダムゴールで独立に再評価**すると、
評価対象のGP最良個体3体すべてで**到達時間が有意に悪化し、成功率も
40〜60%まで低下**した。これは、GP探索が少数評価のノイズに引っ張られて、
「たまたま評価されたゴールに対してだけ調子が良い」個体を選んでしまう
過学習(overfitting)が起きていたことを強く示唆する。

**ノード展開数(探索効率)だけは、世代15/20/27の個体(`ind_000111`)で
統計的に頑健な改善(+51.9%、p<00.001)を示した**——これは
`llm_gp_operation_flow.md`等で触れた「ノード展開数はGazebo評価ノイズと
無関係にサーチループ内部で直接カウントされる」という設計上の理由と
一致する(経路長・到達時間はGazebo/DWA実行というノイズの多いプロセスに
依存するのに対し、ノード展開数は探索アルゴリズム自体の決定論的な出力に近い)。

つまり:

- **ノード展開数の改善は本物**(10回再評価でも頑健)
- **経路長のわずかな改善は個体によっては有意/非有意が分かれ、限定的**
- **到達時間の改善は幻影だった**——実際にはGP実行中に評価されなかった
  ゴールに対して軒並み悪化しており、統計的に有意に「悪化」という結果
  になった
- 成功率(頑健性)自体もGP実行中には見えていなかった弱点であり、進化した
  個体はいずれも初期個体よりゴール範囲全体に対する頑健性が低下していた

## 今後の検討事項

- `repetitions_per_goal`を増やす(現在3)か、fitness評価時のゴールサンプル数を
  増やして、少数サンプルへの過学習を抑える
- 成功率(頑健性)自体をfitnessに組み込む、または生存選択の追加条件にする
- 到達時間・経路長の改善を主張する際は、必ず本レポートのような複数ゴールでの
  再評価を経てから結論づける
