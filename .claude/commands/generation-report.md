---
description: 世代・アルゴリズム比較レポートを作成する
argument-hint: [run_YYYYMMDD_HHMMSS]
---

対象 run: $ARGUMENTS （指定がなければユーザーに確認するか、最新の run を使う）

「世代比較レポート」「アルゴリズム比較レポート」「分析レポートを作って」に応えるため、次の手順で進める。

1. 実験結果ディレクトリ配下の SQLite データベースを探す。
   - 例: experiment_results/**.db
   - 1 回の分析では、1 つの DB とその対応する個体ソース・変更履歴・LLM 呼び出し履歴を明確に対象にする。
   - 解析前に「対象 DB のパス」「対象の個体ソースディレクトリ」「対象分析出力先」を必ず明示する。
   - `/run_YYYYMMDD_HHMMSS/` 形式の run フォルダが指定された場合は、その実行フォルダを優先して使う。例: `experiment_results/run_20260722_153000/`。
2. 既存コードに依存せず、SQLite と個体ソース・変更履歴・LLM 呼び出し履歴から必要な情報を自分で収集してレポートを作る。
3. 出力先は、対象 DB と同じディレクトリに作成された *_analysis 配下、または指定された run フォルダ配下の `analysis/` にし、各実行ごとに別の出力ディレクトリを使うか、既存内容を上書きする前に対象を確認する。
4. もし同名の出力ファイルが既に存在する場合は、必ずその内容が現在の対象 DB 用かどうかを確認してから上書きする。
5. 各世代の最良個体と全世代の最良個体は、それぞれ別フォルダに整理する。
   - 例: `generation_best/` には各世代の最良個体に関する差分・要約を保存する。
   - 例: `overall_best/` には全世代を通じた最良個体に関する差分・要約を保存する。
6. 生成する内容は次を含める。
   - generation_algorithm_report.md
   - generation_comparison.csv
   - individual_comparison.csv
   - metric_comparison.md
   - `generation_best/` 配下の世代ごとの *.diff
   - `overall_best/` 配下の全体最良個体差分
7. レポートでは、初期評価成功数、初期基準個体、初期平均適応度、各世代の成功数/平均適応度、演算種別、最良個体、改善率をまとめる。

必要に応じて、Markdown 形式で要約を示し、重要な個体 ID と適応度を強調する。
